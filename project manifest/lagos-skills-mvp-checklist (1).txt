LAGOS SERVICES — MVP BUILD CHECKLIST
================================

Purpose
-------
Build and launch a minimal Lagos service listing platform quickly,
at minimal cost, using Next.js + Supabase + GitHub + Cloudflare.

Working principle
-----------------
- Build the smallest useful thing.
- Ship early.
- Do not add features outside this checklist unless we explicitly decide to.
- Cross off items in order.
- When something needs rework, update the relevant item rather than starting over.

MVP DATA MODEL
--------------
Profiles:
- id
- user_id (nullable initially)
- name
- bio
- phone
- whatsapp
- location
- avatar_url
- created_at
- updated_at

Services:
- id
- profile_id -> profiles.id
- category_id -> categories.id
- title
- description
- price
- price_unit
- images
- status
- created_at
- updated_at

Categories:
- id
- name
- slug

Relationship:
- One profile can have many services.
- A person creates/owns a profile.
- Each person can add services to their profile as they see fit.
- A service belongs to exactly one profile and one category.
- Public discovery is based on services, while the provider identity lives on the profile.

Initial service status values:
- pending
- approved
- rejected

IMPORTANT DISTINCTION
---------------------
The product is NOT a directory of "skills".

A profile represents a person/provider.
A service represents something that provider offers.
A provider may offer one service or many services.

Example:

Chinedu Okafor (profile)
  -> Plumbing
  -> Electrical installation
  -> Generator repair

Do not duplicate provider identity fields across services.

DEFINITION OF MVP DONE
----------------------
The MVP is DONE when a real person can:

1. Open the website.
2. Search for a service.
3. Browse categories.
4. Open an approved provider listing.
5. See useful service/provider information.
6. Contact the provider through WhatsApp or phone.
7. Create a provider profile and submit a service.
8. Add additional services to the same profile as needed.
9. Have service submissions reviewed by the admin.
10. Have approved services appear publicly under the provider profile.

CONTINUOUS DEPLOYMENT LOOP
--------------------------
Every meaningful change should follow:

1. Make change locally.
2. Test locally.
3. git add .
4. git commit -m "describe change"
5. git push
6. Check deployment/preview.
7. Test the deployed change.
8. If good, keep it.
9. If bad, fix or revert.
10. Cross off the relevant checklist item.
